# Aqara Curtain BLE

通过本地蓝牙控制 Aqara（绿米）HMCN02 窗帘（`lumi.curtain.hmcn02`）的 Home Assistant 自定义集成。
支持打开、关闭、停止和设置位置，无需云端连接或专用网关。

## 支持范围

- 设备型号：`lumi.curtain.hmcn02`。
- Home Assistant：2026.9.1 及以上。
- 配置方式：登录米家获取 LTMK，或手动输入；支持蓝牙自动发现。
- 实体：一个原生窗帘实体，电量、充电状态、电池表面温度、环境光、故障码、运行时间和抱紧状态传感器。
- 控制：开始起床唤醒按钮、识别按钮，以及手拉启动配置开关；所有实体共用同一条蓝牙连接。
- 事件：手动操作、电池告警、设备事件三个实体；仅收到实际设备事件时触发，可用于HA自动化。
- 设备资料：读取厂商、型号、序列号和固件版本；这些信息不创建独立传感器，序列号不进入诊断导出。
- 位置范围：0 表示完全关闭，100 表示完全打开。

提供可选的米家网页登录与已有 LTMK 获取，不提供设备绑定或行程校准。
云端导入已通过模拟 API 和 BLE 测试，完整的真实账号导入及新窗帘验证仍待实测。
本机已有认证与读取实测；长期运行、代理兼容性和新增按钮的实际设备行为仍在验证。
起床唤醒按原厂协议触发35分钟渐开，执行时间可用HA自动化安排；不提供未验证的取消或时长设置。
故障码保留原始数值，避免旧插件与新版规格枚举差异造成误报。可选属性缺失只影响对应实体。
事件解码和HA分发已通过加密模拟通知测试，实际固件是否经本地BLE上报全部12项仍待验证。

## 安装

### 手动安装

1. 将本仓库的 `custom_components/lumi_curtain` 目录复制到 Home Assistant
   配置目录下的 `custom_components/`。
2. 重启 Home Assistant。
3. 进入「设置 → 设备与服务 → 添加集成」，搜索 **Aqara Curtain BLE**。

### HACS 安装

1. 在 HACS 的自定义仓库中添加本仓库，类型选择「集成」。
2. 下载 **Aqara Curtain BLE**，然后重启 Home Assistant。
3. 在「设置 → 设备与服务」中添加集成。

## 配置

配置前，请确保窗帘已在米家完成绑定和行程校准。可登录米家获取密钥，也可手动输入已有 LTMK。

### 从米家获取密钥

1. 添加集成或打开蓝牙发现卡片，选择「使用米家账号」。
2. 选择与米家 App 一致的地区，点击「登录米家」，在新页面完成登录；完成后流程自动继续。
3. 按名称和 MAC 选择窗帘。发现流程只列出对应地址的设备；已添加的窗帘不会重复列出。
4. 密钥获取成功后，关闭米家及其他正在连接窗帘的 App，再继续验证蓝牙连接。
5. 验证成功后完成配置。日常控制只使用本地 BLE，不再访问米家云。

云账号会话只保存在本次配置流程的内存中，成功获取密钥或取消时清理；
配置条目仅保存蓝牙地址和 LTMK，不保存账号密码、登录 cookie 或云令牌。
登录过期或获取失败时按提示重试。暂不支持仅通过家庭共享获得的设备，
请使用绑定设备的账号；选错地区可能无法找到设备。
重新认证同样支持米家登录获取，且只允许更新原设备的密钥。

### 批量开始起床唤醒

在自动化或「开发者工具 → 动作」中选择 **Aqara Curtain BLE：开始起床唤醒**，
可像“打开窗帘”一样选择多个窗帘实体、设备或区域。此动作启动起床唤醒模式，
不需要逐个选择按钮。

```yaml
action: lumi_curtain.wake_up
target:
  entity_id:
    - cover.living_room
    - cover.bedroom
```

也可将 `entity_id` 换成 `area_id: bedroom`，作用于该区域内本集成的窗帘。

### 自动发现

1. 确保窗帘位于本机蓝牙适配器或蓝牙代理的覆盖范围内。
2. 在「设置 → 设备与服务」中找到 **Aqara Curtain BLE** 的发现卡片。
3. 点击配置，选择使用米家账号或手动输入 LTMK，无需输入 MAC 地址。
4. 验证成功后，在 Home Assistant 的完成页面设置设备名称和区域。

发现卡片使用 MAC 地址末尾 6 个十六进制字符区分设备，例如 `Aqara 窗帘 DDEEFF`。
集成检查 MiBeacon 产品标识是否为 `3129`，广播中包含 MAC 时还会核对其与设备地址是否一致。
只有广播不含 MiBeacon 数据时，才使用完整型号名称 `lumi.curtain.hmcn02` 识别。
多个代理发现同一窗帘时只显示一条配置流程；已配置的窗帘不会重复添加。
若广播未提供可识别的型号或产品标识，可手动添加集成并输入蓝牙地址。

### 手动添加

在「设置 → 设备与服务 → 添加集成」中选择 **Aqara Curtain BLE**，
再选择「手动输入 LTMK」。关闭米家及其他连接窗帘的 App，填写以下字段：

| 字段 | 说明 |
| --- | --- |
| 蓝牙地址 | 窗帘的 MAC 地址，例如 `AA:BB:CC:DD:EE:FF` |
| LTMK（32 字节） | 32 字节密钥，以 64 个十六进制字符输入 |

12 字节 token 或 16 字节 beacon bindkey 不能替代 LTMK。
集成会在保存配置前连接设备、验证凭据并读取状态。
验证成功后，在完成页面设置设备名称和区域；之后也可在设备页面修改。
如果设备拒绝已保存的密钥，Home Assistant 会提示重新认证。

密钥保存在 Home Assistant 配置中，请妥善保管配置文件与备份。
诊断导出仅包含设备型号、可用性及窗帘状态，不包含密钥和蓝牙地址。

## 蓝牙要求

需要 Home Assistant 可用的主动连接蓝牙适配器。认证要求 ATT MTU 至少为 71，
以容纳 66 字节的公钥写入和 68 字节的公钥通知。适配器容量不足时，集成会拒绝连接。

### ESPHome 蓝牙代理

无需在 Home Assistant 主机上安装蓝牙适配器。将 ESPHome 代理添加到
Home Assistant 的 ESPHome 集成，代理会转发广播并提供 GATT 连接。
集成使用 HA 选择的可用连接路径，无需填写代理 IP 或指定代理。

ESP32 代理配置需包含以下内容，网络、板型和 API 加密设置沿用代理自身配置：

```yaml
api:

esp32_ble_tracker:

bluetooth_proxy:
  active: true
```

`bluetooth_proxy.active` 控制主动 GATT 连接，与扫描是否为主动模式是两个设置。
仅转发广播的代理无法控制窗帘。每个已连接的窗帘会持续占用一个主动连接槽位，
请确保代理有空闲槽位，且协商出的 ATT MTU 至少为 71。
不同适配器与代理的硬件兼容性仍需分别确认。

## 连接与重试

| 阶段 | 尝试次数 | 单次超时 | 重试间隔 |
| --- | --- | --- | --- |
| 建立蓝牙连接 | 最多 3 轮 | 20 秒 | 2 秒、4 秒 |
| 订阅每个通知特征 | 最多 3 次 | 5 秒 | 2 秒、4 秒 |
| 认证握手 | 每个连接最多 3 次 | 60 秒 | 2 秒、4 秒 |
| 读取状态 | 最多 2 次 | 30 秒 | 断开后冷却 20 秒，再重新连接 |

认证重试优先复用仍连通的蓝牙连接，每次生成新的会话密钥。
暂时没有可连接的广播时，会在每轮连接预算内等待本机适配器或代理收到目标广播。
订阅或认证阶段最终失败后，先断开连接并冷却 20 秒，再进入下一轮连接。
同一集成运行期间，意外断线、命令失败和会话换密钥后的重连也遵守这段冷却时间；
已断线的时间计入冷却，不重复等待完整的 20 秒。重载集成或重启 HA 会清除此计时。
建立可用会话的总预算为 120 秒；含读取重试的单轮状态刷新总预算为 150 秒。
这些预算限制嵌套重试的总等待时间，达到上限即报错。
因此各阶段不保证用完全部尝试次数。分片控制应答最多等待 6 秒，
以容纳设备或代理较慢的 READY/OK；缺失时仍以最终认证或命令应答判断结果。

设备明确拒绝 LTMK 或连接 MTU 不足时立即报错，不重复尝试相同凭据。
连接失败后配置表单保留已输入的 LTMK，可直接重试。
运动命令只发送一次，超时或未收到应答时不会自动重发。

## 状态更新

设备通知会即时更新实体。集成在静止时每 30 秒补读状态，移动时每 2 秒补读。
连接中断后，实体显示为不可用；下次轮询或控制命令会尝试重新连接。

窗帘与传感器共用一个蓝牙会话，每次补读会批量请求以下属性：

| 信息 | MIoT 属性 | 显示方式 |
| --- | --- | --- |
| 当前位置 | `2.6` | 0–100% |
| 运动状态 | `2.3` | 停止、打开中、关闭中 |
| 电量 | `5.1` | 0–100% |
| 充电状态 | `5.2` | 充电中、未充电、不可充电 |
| 电池表面温度 | `3.16` | 原始值除以 100，单位 °C |
| 环境光 | `3.11` | 暗、亮、临界 |

环境光是设备提供的三档状态，不是以 lux 为单位的照度值。
电池信息归入设备的诊断实体。尚未获得有效读数的传感器显示为不可用；
设备拒绝读取某个传感器属性时，其余有效属性仍会更新，不影响窗帘控制。
超出规格范围的读数不替代已确认的值；重连后清空旧会话读数。

集成保持一个主动蓝牙连接，当前不提供空闲断连选项。
收发计数跨越 32768 时继续复用会话。当前候选依据公开设备 SDK 使用普通
32 位计数 nonce；此前 Android 高位规则在首次真机跨界测试中失败，修正待复测。
下一发送计数达到 65536 或最后接收计数达到 65535 时，
下次请求前重新认证并换密钥；不会在原密钥下直接归零。

## 暂停连接

在「设置 → 设备与服务」中禁用此窗帘的集成条目，会卸载集成并释放蓝牙连接。
禁用设备或该设备的全部实体，也会停止轮询、取消正在进行的读取或重试，并释放连接槽位。
只禁用一个实体时，其余启用的实体继续共用连接。
禁用状态会在重新加载或重启后保留，集成不会主动连接已禁用的设备。

重新启用集成条目后会重新连接。重新启用设备或实体时，Home Assistant 通常会在
约 30 秒后自动重新加载条目并恢复连接。名称、区域、凭据和实体标识保持不变。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 无法连接 | 检查蓝牙距离、适配器是否支持主动连接，以及是否有其他应用占用设备 |
| 认证失败 | 确认 LTMK 长度和内容正确；失败后等待约 20 秒再试 |
| MTU 不足 | 使用支持至少 71 ATT MTU 的适配器或代理 |
| 能发现但无法连接 | 确认代理已启用主动连接、有空闲槽位，并关闭其他连接窗帘的应用 |
| 实体显示不可用 | 检查设备供电与蓝牙连接；不可用表示无法确认状态，不代表窗帘已停止或关闭 |
| 位置不准确 | 检查设备是否已完成行程校准 |
| 命令超时 | 先确认窗帘实际状态；命令可能已执行但未收到应答，集成不会自动重复发送 |

反馈问题时，请提供 Home Assistant 版本、适配器或代理型号、复现步骤和诊断信息。
请勿附带 LTMK 或包含凭据的配置文件。

## 开发

开发环境使用 Python 3.14 和 uv。安装依赖后执行检查：

```bash
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked ty check
uv run --locked pytest
```

测试使用 Home Assistant 测试环境与模拟蓝牙设备，实际执行 ECDH、HKDF 和
AES-CCM 运算，无需蓝牙硬件。测试覆盖协议编解码、认证、分片、通知、异常恢复、
配置流程、窗帘服务、传感器和资源清理。代理测试使用 HA 的远端连接路由与模拟 GATT 后端，
验证无需本机适配器的控制和重连。CI 执行相同检查，分支覆盖率门槛为 95%。

### MIoT 架构

| 模块 | 职责 |
| --- | --- |
| `spec.py` | HMCN02 的服务与属性编号、取值范围、读写白名单及枚举值 |
| `protocol.py` | MIoT v2 帧及整数属性编解码，不依赖具体型号 |
| `transport.py` | BLE 认证、加密、分片和请求应答匹配 |
| `coordinator.py` | 共享连接、批量读取、按顺序合并有效读数和控制命令校验 |
| `entity.py` | 共享设备身份与连接生命周期 |
| `cover.py` / `sensor.py` | HA 实体、显示单位和温度换算 |

服务树按 `(SIID, PIID)` 索引，仅声明已支持的属性，不在运行时下载规格或生成全部实体。
原始整数值保留在 coordinator 中，显示换算在实体层完成。
当前位置和运动状态是建立可用会话的必要属性，其余传感器属性允许缺失或读取被拒绝。

实现细节见[协议说明](docs/protocol.md)。
