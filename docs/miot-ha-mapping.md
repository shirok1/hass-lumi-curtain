# HMCN02 MIOT 全量清单与 Home Assistant 映射建议

核对日期：2026-10-23。范围为 `lumi.curtain.hmcn02` 官方 v2 实例，合计 **32 个属性、5 个动作、12 个事件**。这是设计建议，不代表全部能力已实机验证或已实现。新增功能未向设备发送写入；后台计数验证独立运行。

[官方完整规格](https://miot-spec.org/miot-spec-v2/instance?type=urn:miot-spec-v2:device:curtain:0000A00C:lumi-hmcn02:2:0000C817) 与[原厂插件型号映射](/home/shiroki/scale-re/Plugin_1025799/ios/assets/projects/com.lumi.curtain/Main/Common/Spec/lumi_curtain_hmcn02.json)交叉核对；插件控制流程参考[起床唤醒分析](wakeup-mode.md)及[插件提取源码](/home/shiroki/scale-re/analysis/lumi/lumi.textonly.js)。

## 32 个属性

ID 为 SIID.PIID；R读、W写、N通知。配置实体放设备设置，诊断实体放诊断区；低价值诊断项默认禁用。

| --- | --- | --- | --- | --- |
| 1.1 | 厂商 | string / R | 设备厂商信息 | 设备信息；不建独立实体 |
| 1.2 | 型号 | string / R | 设备型号 | 设备信息；不建独立实体 |
| 1.3 | 序列号 | string / R | 设备身份标识 | 设备注册信息；不建独立实体，也不当作公开诊断输出 |
| 1.4 | 固件版本 | string / R | 当前固件版本 | 设备信息；仅有版本读取，不代表能实现固件更新实体 |
| 2.1 | 电机控制 | uint8 / W | 0停止、1打开、2关闭；3为Auto，具体行为未验证 | 已有：cover开/关/停；暂不开放Auto |
| 2.2 | 目标位置 | uint8 / RWN | 0全关、100全开 | 已有：cover位置设置；不另建number重复滑块 |
| 2.3 | 运动状态 | uint8 / RN | 停止、打开中、关闭中 | 已有：cover状态；不另建重复sensor |

## 5 个动作

动作 ID 采用 SIID/A AIID，与同号属性不相同。官方这5项均无输入、输出参数；本集成仍需补充和验证BLE动作帧，不能将动作当成属性写入。

| ID | 作用 | HA 映射与取舍 |
| --- | --- | --- |
| 2/A1 | 电机校准 | 可选配置button/安装流程；先验证执行动作和失败反馈 |
| 3/A1 | 同步上报所有可读属性 | 内部刷新机制；不为常规使用增加按钮，先验证BLE动作编码 |
| 3/A2 | 暂时屏蔽遇阻自动打点 | 高级安装流程内部动作，配合3.24；不做日常开关 |
| 3/A3 | 恢复遇阻自动打点 | 与上一项成对处理；不做日常开关 |
| 4/A1 | 识别设备 | 可选诊断button；设备如何提示仍待验证 |

## 12 个事件

事件 ID 采用 SIID/E EIID。事件是瞬时发生，不能凭一次通知永久推断开关状态。建议合并为手动操作、电池告警、温度告警等少量event实体，不需要12个实体。本地BLE是否上报这些事件及帧格式仍待验证，不能把属性通知当成已支持全部事件。

| ID | 作用 | HA 映射与取舍 |
| --- | --- | --- |
| 2/E1 | 手动打开 | 推荐：手动操作event类型，可触发HA自动化 |
| 2/E2 | 手动关闭 | 推荐：与手动打开合并为一个event实体的不同类型 |
| 3/E3 | 恢复出厂事件 | 内部处理状态失效/重新配对提示；不是恢复出厂按钮 |
| 3/E4 | 极低电量 | 可选：电池告警event类型 |
| 3/E5 | 低电量自动化事件 | 可选：电池告警event类型，与5/E1避免重复提醒 |
| 3/E6 | 异常状态上报 | 可选：故障event；持续故障状态仍读2.4 |
| 3/E7 | 放电温度恢复正常 | 可选：电池温度event类型 |
| 3/E8 | 放电温度过高 | 可选：电池温度event类型 |
| 3/E9 | 放电温度过低 | 可选：电池温度event类型 |
| 3/E10 | 充电中温度过高 | 可选：电池温度event类型 |
| 3/E11 | 充电中温度过低 | 可选：电池温度event类型 |
| 5/E1 | 低电量 | 可选：电池告警event类型，避免和电量阈值自动化重复提醒 |

## 不需要重复建设的功能

- 普通定时开关、星期重复、日出日落：交给HA自动化，不在集成中实现定时器。原厂唤醒定时本身也不是一个额外MIOT属性。
- 渐开唤醒：提供一次触发能力即可，35分钟内逐步开帘由设备功能承担，不在HA循环模拟位置。
- 位置和运动状态：集中在一个cover实体，不重复增加滑块与状态传感器。
- 原生光感和省电时段：这是设备保存的配置，和HA调度器不同。仅有离线自主运行需求时开放；省电时段配置不能简单用HA定时断连替代。
- 不提供通用“写任意MIOT整数”的用户界面，不将工厂老化测试暴露为日常控制。

## 证据差异与实现注意

1. 故障2.4：旧插件仅列0正常/1充电异常/2电池高温，官方v2列0正常及1–4放电高温、放电低温、充电高温、充电低温。先保留原始故障码，按固件验证枚举，不能混用。
2. 起床唤醒2.7：旧插件desc写Identify，但属性名、官方v2和原厂定时调用都指向wake-up-mode。真正识别动作是4/A1。取消和重复触发尚未实测。
3. 省电3.17：原厂插件文案说明01:00–04:30离线，手拉或单击按键可唤醒；官方v2又增加3.25可配置时段，不把旧固定时段套用于所有固件。
4. 3.24官方明确为10–255秒；旧插件desc不准确。它屏蔽的是遇阻自动打点，不等同于禁用所有遇阻保护。
5. 3.21时间编码为高字节起始小时、其次起始分钟、结束小时、结束分钟；3.25官方描述却从最低字节起依次为起始小时、起始分钟、结束小时、结束分钟。两者不能复用同一打包顺序。
6. 3.22官方以星期位全0表示关闭；旧插件还有bit7启用处理。实现原生光感前需核实两者差异，不能根据本表直接写入。
7. 现有读写codec以整数为主；bool、string、uint32写入及独立MIOT动作/事件需要对应实现和验证。逐项发现固件支持情况，不让可选属性读取失败拖垮cover。
8. 设备厂商/型号/版本属于设备注册信息，不需要分别创建sensor；读取固件版本并不等于具备OTA更新能力。

HA映射参考：[Button](https://contributors.home-assistant.io/core/entities/button/)、[Select](https://contributors.home-assistant.io/core/entities/select/)、[Event](https://contributors.home-assistant.io/core/entities/event/)。单次动作使用button，持久可读的选项使用select，瞬时事件使用event；以上具体优先级为本项目设计建议。

## 建议实施顺序

1. 保持连接稳定并完成计数边界实测；保留现有cover、电量、充电、温度、环境光。
2. 增加渐开唤醒按钮、手拉启动开关、故障诊断、行程就绪状态。
3. 增加安装配置：方向、轨道类型、限位、校准、抱紧；验证副作用后默认收在配置区。
4. 按需支持原生光感/省电时段以及事件；不重做HA调度器，不做工厂测试入口。
